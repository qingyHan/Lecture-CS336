# 第一讲补课：UTF-8、BPE 与推理延迟

> 对应[第一讲](../lectures/01_overview_tokenization.md)。这份补充依据学习者初答中的薄弱点整理，不作为对第一讲已全部掌握的认定。

## 1. 字符编码不等于 BPE

UTF-8 把 Unicode 文本转换为字节序列，每个字节的取值范围为 0～255；共有 $2^8=256$ 种基础字节取值。

~~~python
text = "你"
assert len(text) == 1
assert list(text.encode("utf-8")) == [228, 189, 160]
assert len(text.encode("utf-8")) == 3
~~~

一个汉字可以占三个字节，说明基础符号**种类**只有 256 种，并不意味着任意文本最多只有 256 个字节。Byte-level BPE 在这些基本字节的基础上，统计并合并高频相邻 token pair，从而增加词表中的复合 token、可能缩短序列。

要区分：UTF-8 是编码规则；byte token 是建模的最小单位；BPE 是数据驱动的合并训练方法。BPE 并不保证按汉字或自然语言词边界合并。

## 2. pair 的出现次数与非重叠替换次数不一样

原序列：[256, 256, 256]，pair (256,256) 的出现位置为 (1,2) 和 (2,3)，所以统计出现 2 次；两处共享中间位置，不能同时替换。

若新 ID 是 257，规定从左向右进行不重叠替换，输出为 [257,256]，而不是 [256,257] 或 [257,257]。本例的关键约束是**每个旧 token 在一次替换中最多被消费一次**。

## 3. FLOPs 不等于端到端延迟

学习者已独立推导 $QK^\top$ 的 $O(T^2d_k)$ 关系。需要保留的区别是：

- Prefill：通常对整个上下文执行矩阵运算，分数形状可表示为 $T\times T$。
- 带 KV Cache 的单步 Decode：只需一个新 Query 对缓存的 $N$ 个 Key 计算分数，形状为 $1\times N$。
- 端到端耗时还受模型权重读取、KV Cache、batch、kernel、调度及生成 token 数等影响。

例如，若固定开销为 40 ms，另有 60 ms 与 token 数线性相关，token 数减少 30% 后，假设只有线性部分按比例减少，则延迟为：

$$
40+60\times 0.7=82\ {\rm ms},
$$

总延迟减少 18%，不是 30%。这只是教学模型，不能视为 GPU 真实性能。

## 补课结果

学习者已经正确理解“局部计算量下降无法单独决定总耗时”的主张，且 $QK^\top$ 的矩阵形状与乘法次数推导已通过专项验收。UTF-8/BPE 的完整区分、Prefill/Decode 的独立解释仍可在后续复习，不再阻挡第二讲进度。
