>
> **官方资料**：[lecture_13.py](https://github.com/stanford-cs336/lectures/blob/main/lecture_13.py)。官方讲义介绍数据来源、Common Crawl、公开数据集演进，以及版权与隐私问题。本文为原创中文整理，不替代法律意见。

## 1. 为什么数据是语言模型的核心组成？

模型架构决定可以表达什么，优化器决定如何更新参数，数据则强烈影响模型学到哪些语言、事实、风格、领域知识与偏差。公开模型通常详细披露架构，却未必完整披露训练数据，因为数据来源、版权风险、质量控制和配比本身是竞争优势。

数据工作不是简单“把互联网下载下来”。在线服务需要被 crawler 抓取成快照，原始数据还要经历格式解析、正文抽取、过滤、去重、隐私处理、质量评估、采样与混合，才可能成为可训练语料。

## 2. 从 live service 到训练语料

典型管线：

~~~text
在线服务（网页、代码仓库、论文、论坛）
        ↓ crawler / dump / API
原始快照（HTML、PDF、JSON、仓库文件、压缩包）
        ↓ parsing / extraction
规范化文档（文本、结构、元数据）
        ↓ filtering / deduplication / privacy checks
候选训练语料
        ↓ data mixing / sampling / tokenization
训练数据流
~~~

每一步都会改变数据分布。网页抓取覆盖不到登录内容、动态内容或被 robots/条款限制的内容；抽取器可能丢掉表格、代码块和版面信息；过滤器会引入分类偏差；去重可能误删有价值的重复结构。

## 3. 主要数据来源

### 3.1 Common Crawl 与网页数据

Common Crawl 提供大规模网页抓取档案，是很多开放预训练数据集的基础。抓取数据通常包含 WARC 等原始记录、WAT/WET 派生信息或索引。它不是“整个互联网”，而是特定时间、策略和覆盖范围内可访问网页的快照。

常见挑战包括 HTML boilerplate、广告/导航、语言识别、编码异常、网页重复、模板内容和低质量 SEO 文本。数据版本与 crawl 日期会影响可复现性。

### 3.2 Wikipedia、书籍与学术论文

这些来源通常具有更结构化的内容或较高信息密度，但覆盖面、版权许可、时间范围和领域分布不同。论文 PDF 需要解析公式、图表、参考文献与双栏布局；抽取结果可能丢失结构。书籍数据可能有明显的版权与许可约束，不能因为在网上可下载就假定可以自由再分发或训练。

### 3.3 代码与开发者社区

代码仓库、问答网站和技术文档对编程能力很重要，但需要保留语言、文件路径、许可证、依赖关系和代码块边界。仓库中也包含生成文件、vendor 目录、构建产物、密钥误提交、重复 fork 和自动生成代码。简单把所有文件拼成纯文本会损失结构，并可能带来安全与隐私风险。

### 3.4 对话、指令与合成数据

对话与指令数据更多用于后训练或特定 mid-training 阶段。它们可能来自人工标注、用户反馈、合成生成或公开数据集。合成数据的质量取决于生成器、提示、过滤器和验证方式；如果生成器有系统性错误，规模扩大可能放大错误而非修复它。

## 4. 训练阶段与数据分布

一种常见的阶段划分：
- **Pre-training**：大规模通用文本/代码，学习语言统计与广泛知识；
- **Mid-training / continued pretraining**：对特定领域、长上下文或能力分布继续训练；
- **Post-training**：指令数据、偏好数据和强化学习，塑造响应行为与任务策略。

现实系统可能交错使用多个阶段，术语也因组织而异。不要只根据数据文件名判断它属于哪个阶段，应检查实际训练 recipe、采样权重和目标函数。

从大规模、较宽泛的数据向较高质量、更有针对性的数据转移是一种常见设计，但并非“后期数据一定更好”的简单排序。高质量定义依赖目标任务；对代码模型而言，高质量代码数据可能比普通网页更重要。

## 5. 数据集案例与比较维度

课程官方讲义会讨论多个代表性数据集/数据管线，例如 WebText、C4、The Pile、RefinedWeb、Dolma、DCLM、Nemotron-CC 等。学习这些数据集时，不要只记名称；应比较：

| 维度 | 需要核对的问题 |
|---|---|
| 来源与时间 | 从哪些服务/快照收集？哪个时间范围？ |
| 规模 | 文档数、原始字节、去重后 token 数分别是多少？ |
| 抽取 | 如何把 HTML/PDF/仓库转换为文本？ |
| 过滤 | 使用语言识别、质量分类器或规则吗？ |
| 去重 | 文档级、段落级、精确还是模糊去重？ |
| 混合 | 各域采样权重如何设定？是否动态变化？ |
| 法律与隐私 | 许可、条款、个人信息与删除流程如何处理？ |
| 可复现性 | 是否提供代码、版本、hash、过滤器和数据清单？ |

不同论文的“token 数”可能采用不同 tokenizer，因此数字不一定可直接比较。

## 6. 版权、隐私与治理

技术上可抓取不等于法律上可自由使用。数据管线需要考虑服务条款、版权、许可证、隐私、个人信息、删除请求和适用司法辖区。模型训练的法律问题会随地区和案例变化，本笔记只提醒工程风险，不提供法律结论。

从工程治理角度，建议保留来源元数据、抓取时间、许可证/条款状态、处理步骤、删除/排除记录和数据版本。这样才能追溯某个样本为何进入语料，并在发现问题时定位、过滤或重新构建数据集。

## 7. 数据质量的目标依赖性

“高质量文本”没有单一通用标准：
- 语言模型预训练可能需要覆盖广泛领域；
- 数学推理需要可靠推导与答案；
- 代码需要语法、可执行性、依赖和许可证；
- 多语言模型需要语言覆盖与文化分布；
- 安全对齐需要高质量、标注明确的对话与风险样本。

单一质量分类器可能偏向标准书面英语、长文本或特定网站格式，误删少数语言、方言、论坛内容和有价值的非正式文本。过滤策略应结合目标数据与抽样人工审查。

## 8. 常见误区

- “训练数据来自互联网”并不说明来源、覆盖或处理方法。
- 数据集的原始字节、文档数和 token 数是不同量。
- 网页抽取并非无损转换；表格、代码和版面可能丢失。
- 可下载数据不自动意味着可合法再分发或训练。
- 合成数据的数量不等于真实监督质量。
- 质量过滤会改变分布，可能损害某些子群体/领域。
- 没有版本与来源记录，就很难复现实验或响应数据删除要求。
