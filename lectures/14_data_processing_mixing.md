## 1. 数据管线是可测量的算法系统

原始数据通常不是可直接训练的纯文本：网页是 HTML，论文是 PDF，代码是仓库目录，论坛数据可能是 JSON 或数据库导出。转换、过滤和去重都可以视为把原始集合 R 转换成更适合目标任务的子集或表示。每一步都应有输入输出、统计指标、版本和错误分析。

一个实用管线：

~~~text
原始抓取 → 解析/正文抽取 → 规范化
       → 语言与质量过滤 → 精确/模糊去重
       → 域分类与数据混合 → tokenizer → 训练
~~~

必须在各阶段记录文档数、字节数、token 数、语言分布、域分布、丢弃率和错误样例。只报告最终 token 总量会掩盖数据被过滤器系统性改变的事实。

## 2. 文本抽取与规范化

网页抽取的目标是保留正文并删除导航、广告、页脚和模板。常见工具有 trafilatura、resiliparse、jusText 等；不同工具对表格、列表、代码、引用和多栏内容的处理不同。PDF 可能需要 OCR、版面分析和阅读顺序恢复。代码仓库需要保留文件路径、语言、注释、README 与依赖结构。

规范化可能包含 Unicode 处理、空白标准化、URL/HTML entity 解码、异常字符清理和 metadata 提取。规范化必须谨慎：过度清理可能删除代码缩进、数学公式、语言标记或有意义的标点。

## 3. 过滤：从目标样本学习一个筛选器

设目标集合 T 表示我们希望保留的文本类型，原始语料为 R。目标是为每个样本 x 计算一个分数，再选择子集 R'。过滤器可以是规则、语言识别器、质量分类器、毒性分类器或基于语言模型的打分器。

一种形式化写法：

$$
s(x)=\operatorname{score}(x;T),\qquad
R'=\{x\in R:s(x)\ge\tau\}.
$$

阈值 τ 控制保留率与精确度之间的权衡。真实系统常采用随机采样而不是硬阈值，以保留分数接近边界的样本或控制域比例。

### 3.1 常见过滤任务

- **语言识别**：保留目标语言，但短文本、代码、多语混合内容容易误判。
- **质量过滤**：识别信息密度、可读性或内容质量；分类器可能偏好规范格式，忽略有价值的口语或非主流领域。
- **毒性/安全过滤**：排除或单独标记有害内容；误删会影响对真实世界语言和安全问题的覆盖。
- **领域过滤**：保留代码、科学、数学等目标域；需定义域标签并评估分类器偏差。

### 3.2 过滤的验证

抽样人工检查过滤前后样本，估计 precision/recall、保留率与各域分布变化。过滤器只在与训练目标相匹配的标注集上评估，可能产生分布偏差。要保留失败样例，而不是只看总体准确率。

## 4. 精确去重

精确去重识别相同或完全一致的文档/片段。最简单方法是对规范化内容计算 hash，将相同 hash 的样本归为重复项。对大规模数据，hash 能减少存储和比较成本。

注意：
- 规范化规则决定“相同”的含义；
- hash 碰撞理论上可能存在，严格系统可在 hash 相同时再比较原文；
- 文档级去重不能自动消除文档内部重复段落；
- 如果不同来源的同一文本具有不同 metadata，应定义保留哪个来源或合并 metadata 的规则。

## 5. 模糊去重：Shingling、Jaccard、MinHash 与 LSH

两个文档可能只有部分重叠。可先把文本切成 n-gram/shingles 集合 A、B，再用 Jaccard 相似度衡量重叠：

$$
J(A,B)=\frac{|A\cap B|}{|A\cup B|}.
$$

直接比较所有文档对的成本为 (O(N^2))，大语料不可行。

### 5.1 MinHash

MinHash 用多个随机 hash 近似集合的 Jaccard 相似度。对一个 hash 排列 h，两个集合最小 hash 相同的概率满足：

$$
\Pr[\min h(A)=\min h(B)]=J(A,B).
$$

使用 k 个独立/近似独立的 hash 函数，可用签名中相同位置的比例估计 Jaccard。估计方差随签名长度增加而降低，但签名更长会增加计算和存储成本。

### 5.2 Locality-Sensitive Hashing（LSH）

LSH 将 MinHash 签名划分为多个 band，每个 band 作为候选键。若两个签名在至少一个 band 完全相同，就把文档对加入候选集合，再计算更精确的相似度并决定是否去重。

LSH 的目的不是保证找到所有重复，而是用可控的候选生成成本，较高概率召回相似项。阈值、band 数、每 band 行数会改变召回率和误报率。必须用人工标注或已知重复对验证候选质量。

### 5.3 过度去重的风险

重复内容可能是低价值的模板，也可能是有意义的格式、定义、代码 API、经典文本或刻意重复的训练信号。删除过度会改变分布；去重应记录规则、阈值、文档级/段落级粒度与保留策略，并在下游训练上评估效果。

## 6. Data Mixing：如何混合不同来源？

假设有 K 个数据域，训练时以权重 (p_i) 采样第 i 个域，满足 (p_i\ge0) 且 (sum_i p_i=1)。最简单的混合是按原始数据比例采样，但大规模语料中高资源域可能淹没小而有价值的域。

提高某个域的采样权重可以改善相关能力，也可能过度重复小数据集或损害通用分布。混合策略可以依赖目标任务、数据质量、域规模、模型容量和训练阶段。

可执行的研究流程：
1. 定义域与目标评估集；
2. 先用小模型/小预算比较几种 mixture；
3. 控制总训练 token 与训练 recipe；
4. 评估整体 loss 和分域/下游能力；
5. 估计不同 mixture 的方差与重复采样程度；
6. 以实验结果而非直觉决定最终权重。

## 7. 合成数据与后训练数据

合成数据可用于指令跟随、数学推理、代码任务和偏好训练。关键不只是生成量，而是生成器的能力、任务分布、验证机制和过滤流程。若 teacher 生成错误推导，而数据只按流畅度筛选，student 可能学习到系统性错误。

对数学或代码，可使用可验证规则、单元测试、执行器或形式化 grader；对开放式对话，则可能需要人工/模型偏好判断并进行抽样审计。合成数据应标记生成器版本、提示、采样参数、验证器和过滤标准，避免未来无法追溯。

## 8. 可复现的数据实验

至少保存：
- 数据源与版本；
- 抽取工具和参数；
- 规范化规则；
- 过滤器模型/版本/阈值；
- 去重算法、shingle 大小、hash/MinHash/LSH 配置；
- 各阶段样本数与 token 数；
- 混合权重和采样随机种子；
- 人工抽样审核结果；
- 下游训练配置与评估结果。

大规模原始语料不一定适合放进 Git。仓库应保存下载脚本、官方链接、版本号、校验和与处理代码；数据文件放在符合许可的外部存储。

## 9. 常见误区

- 精确去重与模糊去重解决不同问题。
- Jaccard 适合集合相似度，不直接表达语义等价。
- MinHash 是概率估计；签名长度有限会有方差。
- LSH 产生候选集，不等于候选对必然重复。
- 过滤器的总体准确率可能掩盖某些语言/领域的高误删率。
- 数据混合比例改变会影响能力分布，不只是改变训练速度。
- 合成数据的规模不能替代验证与质量控制。
- 删除重复数据可能减少有害重复，也可能删除有用的自然频率信息。
