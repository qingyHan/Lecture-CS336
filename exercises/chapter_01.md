## 参考答案（完成练习后展开）

<details>
<summary>展开第一讲参考答案与推理</summary>

1. Token ID 是 embedding table 的行索引，不是语义量尺。ID 100 不比 ID 20“语义更大”。
2. Python len(text) 统计 Unicode 码点数；len(text.encode("utf-8")) 统计字节数。例如地球 emoji 的码点数为 1，UTF-8 字节数为 4。
3. 字符级词表通常较小但序列较长；字节级基础值固定 256 但序列可能更长；词级常见词序列短但词表大且可能 OOV；BPE 合并常见片段，在词表与序列长度间折中。
4. BPE 按语料相邻 pair 的频率合并，不使用词根、词缀或语法规则；空格、标点、代码片段也可能参与合并。
5. ababab 的 pair 计数为 (a,b):3、(b,a):2。第一轮为 [ab,ab,ab]，第二轮为 [abab,ab]；新 ID 为 256、257，最终编码 [257,256]。重叠候选不能同时替换。
6. A=1200/400=3 bytes/token；B=1200/300=4 bytes/token。压缩指标不能单独证明模型质量。
7. 注意力平方项从 1000² 降到 500²，即原来的 1/4；FFN、固定开销、访存和调度不随同一比例变化。
8. Round-trip 只验证往返重建，不验证压缩率、速度、模型质量或 tokenizer 与模型是否匹配。
9. 必须先合并 (a,b) 才会产生 token ab；若先应用第二条规则，原序列里还没有 ab token。
10. 测试空串、标点、多语言、emoji、重复片段和组合字符；检查往返一致性，并对关键 merge 结果作独立断言。
11. 需说明词表预算、语言覆盖、未知文本处理、上下文预算和成本，并设计控制变量明确的对照实验。
12. 固定语料与其它规则，只改变 merge budget；测量词表大小、bytes/token、编码速度和模型质量，明确区分预期与实测。
13. QKᵀ 形状 (4,4)，有 16 个分数；每个点积 3 次乘法、2 次加法；T 从 4 到 8，分数数变为 4 倍。
14. L(1000)=100 ms；L(700)=75.7 ms；延迟下降 24.3%，不是 30%。这是教学假设，不是 GPU 实测。
15. 单步 Decode 分数形状 (1,100)，Prefill 分数形状 (100,100)；Decode 仍受 KV Cache、权重读取与生成步数影响。
