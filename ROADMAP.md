## 1. 课程终点与能力目标

完成课程后，目标是能够：

1.  从原始文本到 token ID，解释并实现分词流程。
2.  从数学定义实现 Transformer
    语言模型的关键组件，并理解损失函数、优化器与训练循环。
3.  用 FLOPs、显存、带宽、算术强度和关键路径估算工作负载。
4.  读懂 GPU kernel 的执行模型，能对模型和算子做 profiling、benchmark
    与正确性测试。
5.  理解张量并行、数据并行、流水线并行等分布式训练/推理的通信代价。
6.  使用实验数据拟合和解释 scaling laws，而不是只记住经验公式。
7.  处理大规模预训练数据，设计过滤、去重、混合与数据质量实验。
8.  评估语言模型，并理解监督微调、偏好优化与基于可验证奖励的强化学习。
9.  在给定数据、算力、延迟和质量约束下，提出可验证的系统设计方案。

## 5. 计算资源分级

- **默认设备：GPU。** 用户的实际环境具备 GPU 与 PyTorch，因此凡是需要在 CPU/GPU 中选择、且任务在 GPU 上有意义时，默认选择 GPU。
- **GPU 优先**：小型语言模型训练、推理性能实验、Triton/kernel benchmark、混合精度、显存测量与多卡实验。
- **CPU 例外**：仅在测试 CPU 特有行为、依赖不支持 GPU、需要验证纯 Python 逻辑，或明确做 CPU/GPU 对照时使用 CPU。
- **多 GPU/分布式**：优先按可用 GPU 设计通信与分片实验；若硬件数量不足，明确记录实际卡数，不用模拟结果冒充真实性能。
- **高成本实验**：先确认官方 handout 的配置和数据要求，先做小预算正确性验证，再扩展训练规模。
- **数据下载**：允许下载原始数据集与权重；大文件不直接提交 Git，保留官方 URL、下载脚本、版本/校验信息，并说明需要学习者手动下载的项目。
- **性能结论**：必须记录 GPU 型号、驱动/CUDA、PyTorch、dtype、batch、shape、warm-up、同步方式和重复次数；CPU 结果不能替代 GPU 性能证据。

## 6. 第一阶段的正式学习顺序

1.  Lecture 1：课程导论与 Tokenization。
2.  Lecture 2：PyTorch / einops 与资源核算。

5.  A1 的实现按依赖分解为 tokenizer → 模型组件 → 优化器/训练循环 →
    小模型训练与评估。

第一讲先建立整体地图和 tokenizer
的直觉，不要求先掌握完整深度学习。第一讲的 BPE
实现是教学用的简化版本，重点是算法机制；它不等于官方生产 tokenizer
的完整规范。

## 7. 验收标准

每个主题分别记录四种状态，不能互相替代：

1.  **概念掌握**：能不用原文解释核心概念、适用条件与局限。
2.  **数学掌握**：能从定义推导关键公式，且维度/单位正确。
3.  **实现掌握**：能独立编写实现并通过边界测试。
4.  **实验掌握**：能说明假设、基线、变量、指标、观察结果与局限。

只有在对应证据写入 `PROGRESS.md` 后，才更新状态。
